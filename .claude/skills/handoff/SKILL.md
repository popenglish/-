# /handoff — 引き継ぎ書の作成

このスキルが呼ばれたら、ここまでの会話と作業内容を「引き継ぎ書」として1つのMarkdownファイルにまとめ、保存する。
目的：**次のセッション（または別の人）が、この文書だけを読めば続きから作業できる**ようにすること。

引数（args）があれば、その内容（例：特定のクラス名やタスク名）に絞った引き継ぎ書にする。なければ作業全体をまとめる。

## 手順

1. **会話全体を振り返り、以下を整理する**
   - **作業の目的**：何を作ろうとしているか（1〜3行で）
   - **完了したこと**：具体的な成果物を漏らさず書く
     - スプレッドシート・GoogleドキュメントのID・URL・名前
     - タブ（シート）の名前は**実際の表記のまま正確に**（全角・半角・漢数字の違いが事故のもとになるため）
     - 使っている数式は**そのままコピーできる形で全文**載せる
     - Apps Script（GAS）のスクリプト名と役割
   - **未完了・保留中のタスク**：何が残っているか、どこまで進んだか
   - **決まっているルール・注意点**：例「タブ名に算用数字（1,2…）を使わない。漢数字（中一A）を使う」「貼り付けはセルを1回クリックしてから⌘V」など、過去のトラブルから決めたルール
   - **起きた問題とその解決方法**：同じ問題を繰り返さないため
   - **次のセッションで最初にやること**：具体的な1歩目を書く
2. **`handoffs/` フォルダがなければ作る**
3. **ファイルとして保存する**
   - ファイル名：`handoffs/handoff-YYYY-MM-DD.md`（日付は `date +%F` コマンドで取得。同じ日に2回目以降は `-2`, `-3` を付ける）
4. **git にコミットしてプッシュする**（このリポジトリの指定ブランチへ）
5. **ユーザーに日本語で報告する**
   - このユーザーは日本語話者で、パソコンの専門用語に慣れていない。専門用語を避け、やさしい言葉で「引き継ぎ書を保存しました。次回は『handoffs フォルダの◯◯を読んで続きをして』と伝えれば続きができます」と案内する
   - 引き継ぎ書の内容の要約（完了したこと・残っていること）も短く添える

## 引き継ぎ書のテンプレート

```markdown
# 引き継ぎ書（YYYY-MM-DD）

## 作業の目的
（何を作っているか）

## 使っているファイル一覧
| 名前 | 種類 | ID / URL | メモ |
|---|---|---|---|
（スプレッドシート、Googleドキュメント、スクリプトなど全部）

## 完了したこと
（成果物ごとに。タブ名・数式は正確にそのまま書く）

### 重要な数式（コピペ用）
（実際に使っている数式を全文。どのタブのどのセルに入れるかも書く）

## 未完了のタスク
- [ ] （残っている作業。どこまで進んだかも書く）

## 決まっているルール・注意点
（過去のトラブルから決めたルール）

## 起きた問題と解決方法
（問題 → 原因 → 直し方）

## 次のセッションで最初にやること
1. （具体的な1歩目）
```

## 注意

- 「たぶん」「おそらく」で書かない。会話で**確認できた事実**と**未確認のこと**を区別して書く
- 数式・ID・タブ名は要約せず**原文のまま**載せる（1文字違うと動かなくなるため）
- ユーザーへの返事は必ず日本語で
